# 📚 Knowledge Agent: Book Management

이 스킬은 사용자가 자연어로 독서 기록을 관리하고, 외부 API를 통해 도서 정보를 수집하며, AI 분석을 통해 독후감 기록 및 도서 추천을 수행하는 기능을 제공합니다. 모든 데이터는 사용자의 Notion Database에 구조화되어 저장됩니다.

## 1. 도서 정보 자동 수집 (ISBN -> Notion)
사용자가 ISBN을 입력하면 도서 정보를 검색하여 Notion에 저장하거나 읽은 횟수를 업데이트합니다.


## [Step 0] Prerequisites (환경 설정 및 DB 준비)
스킬 실행 전 필수 환경을 점검하고 데이터 저장소를 초기화합니다.

1. **API Key 검증**: BRAVE_SEARCH_API_KEY, NOTION_API_KEY가 환경 변수에 설정되어 있는지 확인합니다.
2. **상위 페이지 확인**: Notion 내에 "AI 독서 기록장" 페이지가 있는지 검색하고, 없을 경우 생성합니다.
3. **독서 DB 생성**: "AI 독서 기록장" 하위에 "독서 DB" 페이지(데이터베이스)가 있는지 확인합니다.
   - **DB가 없을 경우**: 아래의 스키마를 사용하여 생성합니다.
   - **Schema 구성**:
     * title: 도서명 (Type: title)
     * ISBN: ISBN 번호 (Type: rich_text)
     * author: 저자 (Type: rich_text)
     * publisher: 출판사 (Type: rich_text)
     * read_count: 읽은 횟수 (Type: number, Initial value: 0)
     * summary: 요약 (Type: rich_text)
     * keywords: 핵심 키워드 (Type: multi_select)
     * status: 상태 (unread/reading/completed)
     * review: 독서 감상문 (Type: rich_text)
     * rating: 별점 (1 ~ 5)
     * created_date: 처음 기록한 날짜 (Type: rich_text)
     * last_updated_date: 마지막으로 기록한 날짜 (Type: rich_text)
     * is_favorate: 즐겨찾기 여부 (Type: rich_text)

## [Step 1] Search & Identification (도서 식별)
사용자 입력으로부터 도서를 특정하고 메타데이터를 수집합니다.

### 1-1. 사용자 입력 파싱
**입력 형식 A (Title)**: "XXX 라는 타이틀 책을 이제 읽으려고 해/읽었어. 기록해줘"
**입력 형식 B (ISBN)**: "XXX 라는 ISBN 책을 이제 읽으려고 해/읽었어. 기록해줘"

### 1-2. 정보 수집 및 확인 루프
사용자가 입력한 값(Title 또는 ISBN)을 바탕으로 도서 정보를 수집하고 사용자의 확인을 받습니다. 이 과정은 최대 **5회**까지 반복할 수 있습니다.

1. **검색 실행**: Brave Search API를 사용하여 책이름, 출판사, ISBN, 저자, 요약, 키워드 정보를 수집합니다.
2. **정보 정제**: Gemini AI가 검색 결과에서 필요한 항목(제목, 저자, 출판사)만 추출하여 사용자에게 제시합니다.
3. **사용자 컨펌**: "찾으시는 책이 [제목 - 저자 - 출판사]가 맞나요?"라고 질문합니다.
    - **"맞아"라고 할 경우**: [Step 2] 저장 단계로 진행합니다.
    - **"아니"라고 할 경우**: 검색 결과가 부적합하다고 판단하여 루프를 재시작합니다.
4. **예외 처리 (Fallback)**:
    - 루프가 **5회 이상** 반복되어도 도서를 특정하지 못할 경우, "도서 정보를 찾을 수 없습니다"라고 알립니다.
        - 사용자에게 직접 **[도서명, 저자, ISBN]** 정보를 입력해달라고 요청하여 수동으로 기록 절차를 밟습니다.
    - 검색 결과를 찾지 못한 경우, "도서 정보를 찾을 수 없습니다. 다시 입력해 주세요"라고 알리고 루프를 재시작합니다.


## [Step 2] Save & Sync (노션 DB 저장)

확정된 데이터를 바탕으로 Notion 데이터베이스의 상태를 업데이트하거나 신규 생성합니다.

### 2-1. 기존 데이터 조회 및 업데이트 (Upsert 로직)
1. **중복 체크**: 수집된 **ISBN**을 기준으로 Notion DB 내 동일 도서 존재 여부를 조회합니다.
2. **기존 도서 존재 시 (Update)**:
    - 해당 페이지의 `read_count` 값을 읽어와 **+1** 처리합니다.
    - '마지막 읽은 날짜' 혹은 '최근 업데이트' 필드를 오늘 날짜로 갱신합니다.
    - 사용자에게 `"이미 읽으신 적이 있는 책이네요! 누적 독서 횟수가 [N]회로 업데이트되었습니다."`라고 알립니다. [종료]

### 2-2. 신규 데이터 등록 (Create)
DB에 책이 없을 경우, [Step 1]에서 수집한 정보를 바탕으로 대이터를 매핑합니다.
* **매핑 항목**: 
    - **Title**: 도서명
    - **Author**: 저자
    - **Publisher**: 출판사
    - **ISBN**: ISBN 번호
    - **Summary**: 도서 요약 내용
    - **Read Count**: 1 (초기값)
    - **Status**: 사용자의 입력 문맥에 따라 'reading' 또는 'completed'으로 설정

### 2-3. 최종 완료 보고 및 사후 액션 제안
1. **완료 알림**: `"무사히 저장되었습니다! [도서명 - 저자] 정보를 노션 서재에 등록했습니다."`
2. **독후감 제안 (완독 맥락)**:
    - 만약 사용자가 **완독(completed)** 상태로 기록했으나 아직 독후감을 작성하지 않았다면 질문합니다.
    - **질문**: `"이 책을 벌써 다 읽으셨군요! 혹시 간단하게 독후감도 남겨두시겠어요? (500자 이내)"`
    - **응답 처리**:
        - **YES**: **2. 독후감 기록**로 이동하여 독후감을 입력받고 저장 절차를 다시 밟습니다.
        - **NO**: `"기록을 완료했습니다."`라고 알린 후 **[종료]**합니다.

## 2. 독후감 기록 
책 제목으로 도서를 특정하여 독후감을 작성하고 저장합니다.

## [Step 0] Prerequisites (환경 설정 및 사전 확인)
스킬 실행 전 필수 환경을 점검하고, 기존 DB에 도서가 등록되어 있는지 우선 확인합니다.

### 0-1. 도서 중복 및 존재 여부 확인
사용자 입력(Title 또는 ISBN)을 바탕으로 Notion DB에 해당 도서가 이미 등록되어 있는지 조회합니다.

1. **조회 결과 있음**:
    - 해당 도서의 정보를 불러와 **[Step 1]**(기존 데이터 업데이트)로 즉시 이동합니다.

2. **조회 결과 없음 (책이 없는 경우)**:
    - 사용자에게 다음과 같이 질문합니다: `"해당 도서가 DB에 없습니다. 새로 검색하여 등록하시겠습니까? [Y/N]"`
    - **[YES]**를 선택할 경우: **1. 도서 정보 자동 수집** 단계로 진입하여 프로세스를 이어갑니다.
    - **[NO]**를 선택할 경우: `"독서 기록을 종료합니다."`라는 메시지와 함께 프로세스를 **[종료]**합니다.

3. **환경 변수 체크**: 
    - `BRAVE_SEARCH_API_KEY`, `NOTION_API_KEY` 설정 여부를 상시 확인합니다.

## [Step 1] Input (입력 받기)

### 1-1. 기본 입력 파싱
- 사용자의 첫 발화를 분석합니다. 
- (예: "XXX이란 책에 독후감을 쓰고 싶어", "XXX 완독했어. 독후감 써줘")
- 도서 제목 혹은 ISBN을 추출한 뒤 **1-2**로 이동합니다.

### 1-2. 독후감 입력 및 글자 수 검증
- 사용자에게 독후감 내용을 입력받습니다.
- **검증 규칙**: 입력받은 독후감이 **500자 이하**인지 확인합니다.
    - **500자 이하인 경우**: 정상 수락 후 **[Step 2]**(정보 수집)로 이동합니다.
    - **1-2-1. 500자 이상인 경우**: `"독후감이 너무 깁니다. 500자 이내로 줄여주세요."`라고 알리고 다시 입력을 기다립니다
    - **1-2-2. 이미 독후감이 있는 경우**: '"이미 독후감이 있습니다. 덮어쓰시겠습니까?"' 라고 질문합니다.
    - **YES의 경우**: **[Step 2]**로 이동해서 프로세스를 이어갑니다.
    - **NO의 경우**: '"알겠습니다. 그럼 독후감 쓰는걸 취소하겠습니다"' 라고 알리고 프로세스를 **[종료]**합니다.

### 1-3. Step 1 예외 처리 (Exception Handling)
- **도서 식별 불가**: 입력값에 도서명/ISBN이 누락된 경우, 사용자에게 도서명을 먼저 묻습니다.
- **모호한 검색 결과**: DB 내 동일 제목이 여러 개일 경우, 출판사나 저자를 확인하여 하나를 특정합니다.
- **독후감 누락**: 명령만 있고 내용이 없을 경우, "500자 이내로 독후감 내용을 입력해 주세요"라고 요청합니다.
- **글자 수 초과 반복**: 500자 초과 입력을 지속할 경우, "입력하신 내용의 앞부분 500자만 저장할까요?"라고 대안을 제시합니다.



## [Step 2] 저장 (Save & Update)

### 2-1. 노션 DB 업데이트
- **저장 위치**: [Step 1]에서 입력받은 독후감을 **Notion의 "AI 독서 기록장" 하위 "독서 DB" 페이지 내 해당 도서의 `review` 섹션**에 저장합니다.
- **수행**: 
    - 기존에 작성된 `review`가 있다면 새로운 내용으로 덮어쓰거나 추가합니다.
    - `last_updated_date`를 오늘 날짜로 갱신합니다.

### 2-2. 최종 완료 보고
- 저장이 완료되면 사용자에게 결과를 알립니다.
- 알림: `"독후감이 [도서명] 페이지의 review 섹션에 무사히 저장되었습니다!"` [종료]

### 2-3. 예외 처리 (Exception Handling)
- **도서 미검색**: DB에 해당 도서가 없을 경우, "책이 없습니다. 새로 등록하시겠습니까?"라고 묻고 [1. 도서 정보 자동 수집] 스킬로 유도합니다.
- **입력 누락**: 독후감 내용 없이 명령만 내릴 경우, "기록할 내용을 말씀해 주세요 (500자 이내)"라고 요청합니다.
- **기존 기록 존재**: 이미 리뷰가 작성되어 있다면, "기존 독후감이 있습니다. 덮어쓸까요, 아니면 아래에 추가할까요?"라고 확인합니다.
